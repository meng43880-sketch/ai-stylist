# MARKETPLACE_INTEGRATION — что подключено, а что нет

Дата: 2026-09-27. Проверено живыми пробами с сервера (WB: 403/block, Ozon: антибот-403).

## Что уже реально подключено

- **Wildberries, живой поиск** — открытый API `search.wb.ru` (без ключа):
  `backend/lib/market.js` → `wbSearchServer()` + нормализация в единую модель
  `Product` (реальные название, цена, фото, рейтинг, число оценок, цвета,
  размеры, ссылка на карточку). Фото — CDN-паттерн basket (таблица vol→host
  может дрейфовать, закрыто onerror-заглушкой).
- **Пути живья**: `GET /api/market/wb/search`, `POST /api/market/score`,
  режим `DATA_SOURCE=hybrid` (живьё + демо-добор), прямой запрос из браузера
  (`WBClient` во frontend — у WB открытый CORS).
- **MarketplaceService** (`MarketplaceService.search/getProduct/getReviews/
  getAvailability`): параллельный поиск по провайдерам, merge, dedupe;
  падение одного провайдера не роняет остальных.
- **CatalogProvider**: `DemoCatalogProvider`, `WbPublicCatalogProvider`,
  `OzonCatalogProvider` (бросает честное `NO_SOURCE`). Замена источника —
  без изменения AI и frontend.
- **Explanation API**: `GET /api/products/:id/explanation` и
  `POST /api/products/explanation` (для живых товаров из кэша frontend) —
  score + breakdown считает RecommendationEngine, формулировки честные.
- **Availability API**: `GET /api/products/:id/availability`.
- **AI-шлюз**: `OFOX_API_KEY/OFOX_BASE_URL` + `QWEN_*_MODEL`
  (`qwen/qwen3.8-flash` для vision/stylist, `qwen/qwen-flash` для product).
  Без ключей — `DEMO_MODE=true`, всё работает локально.
- **Frontend**: фильтр Все / WB·живьём / Демо на странице результата,
  маркетплейс + рейтинг + число отзывов на карточке, «Купить на Wildberries»
  ведёт на реальную карточку, демо — на поиск с пометкой о demo-ценах.

## Что работает только в Demo Mode

- Каталог из 24 товаров, демо-отзывы (`source: demo`), демо-анализ товаров
  (с полем `confidence`), Vision/Stylist-диалог без ключей.
- Наличие демо-товаров помечается `availability.demo: true`.

## Вход через WB и партнёрка (сентябрь 2026)

- **WB ID** (единый аккаунт): существует, но интеграция в сторонние сервисы
  только тестируется с B2B-партнёрами (первый — Профи.ру). Открытого OAuth
  для всех нет. В коде уже есть `backend/lib/auth.js`
  (`LocalAuthProvider` сейчас, `WbIdProvider` — когда WB откроет программу):
  тогда добавится кнопка «Войти через WB ID», frontend-логика не меняется.
- **Партнёрка (работает сейчас)**: CPA-сети (Admitad/Indoleads, 1–9% revenue
  share) + Wibes для блогеров. В коде: `AFFILIATE_WB_PREFIX` /
  `AFFILIATE_OZON_PREFIX` в `.env`, endpoint `GET /api/market/link` оборачивает
  любую исходящую ссылку; без префиксов — прямые ссылки. Регистрация в CPA —
  за тобой, код уже ждёт.

## Открытые датасеты (open data) — работают прямо сейчас

Живой поиск WB/Ozon блокируется по сети, поэтому подключён открытый снимок:
**Bright Data WB sample (1001 товар, дек 2024)** → `backend/lib/datasets.js`.

- CSV качается сам в `backend/data/datasets/` при первом поиске (2.4 МБ),
  парсится без зависимостей, не fashion-строки отсекаются по категориям
  (~220 позиций одежды/обуви/аксессуаров)
- Маппинг: реальное название, цена, старая цена, фото (basket CDN), рейтинг,
  число оценок, цвета и размеры из вариаций, состав, ссылка на карточку
- Маркировка: `source: 'dataset:...'`, дата снимка; в UI — «Открытые данные WB
  (дек 2024): цена могла измениться». Текстов отзывов в снимке нет — не выдумываем
- Поиск: токены запроса + фильтры категории/цены/цвета; скоринг тем же движком
- Добавить базу: строка в `SOURCES` + при необходимости `columns()` под её колонки.
  Ozon в открытом виде не найден (проверены HF, Kaggle, GitHub)
- Следующий масштаб: дамп `nyuuzyou/wb-products` (160 млн, zstd/jsonl, без цен
  и фото) — требует отдельную инфраструктуру распаковки и индексации

## Community-база: товары от пользователей (своя база через расширение)

Принцип: пользователь **явно делится конкретной карточкой** (кнопка «сохранить»,
как в Pinterest) — никакого silent-скрейпинга. Позже это ляжет в основу
браузерного расширения: content-скрипт на странице WB/Ozon читает DOM
(название/цена/фото/рейтинг — всё есть в разметке) и шлёт сюда же.

- `POST /api/collect` (с токеном): `{url, title, price, img?, brand?, colors?[], sizes?[], rating?}` →
  валидация (только карточки WB/Ozon, санитизация, лимит 50/день) → дедуп по
  артикулу → `source: 'community'`, хранится с автором и датой
- `GET /api/collect/search` — поиск по базе
- Общая воронка подмешивает community в рекомендации с тем же скорингом;
  `getProduct` смотрит сначала в community (свои данные точнее живых)
- Таблица `community`, переживает редеплои вместе с остальной PG-базой

## Воронка кандидатов (экономия токенов)

```text
Веер запросов (до 3) × 1 страница WB (по 25) → ~50 кандидатов
  → код-фильтры (цена/размер/категория) → скоринг всех → топ-50
  → AI#3 только по новичкам без кеша (макс. 8 за поиск, ключ кеша
     marketplace+id+7 дней; без ключа — честные сигналы из рейтинга)
  → топ-50 в API → топ-12 в чат-пузырь, все 50 на странице результата
  → AI#2 пишет только текст ответа
```

AI никогда не видит сотни товаров. Прямой поиск из браузера тянет 3 страницы
(до 90), скоринг — `POST /api/market/score` (лимит 100).

## Токены за запрос (замер по промптам, без ключа — нули)

- AI#3: ~350 токенов/товар (~145 in + ~200 out) × макс. 8 новичков = **~2,8k/поиск**
- AI#2: ~450–600/реплику (EN-системник + история 4 сообщения + короткий ответ)
- AI#1: ~1k/фото (картинка + JSON, max 600 токенов на выход), один раз, кеш по хешу
- Итого типичный запрос с живьём: **~3,5k токенов**
- Экономия: system-промпты на английском (кириллица ≈ 2 симв/токен, латиница ≈ 4),
  история 8→4 с обрезкой, лимит запроса 500 символов, `max_tokens` на выходах
  (350/500/600) — защита от развёрнутых ответов, главного пожирателя бюджета
- Реальный расход: `GET /api/status` → поле `usage` (in/out/calls по тегам
  vision/stylist/product), деньги — в дашборде ofox

## Важно про официальные Seller API

Seller API WB/Ozon **не дают полный публичный каталог** — только данные
своего продавца. Для «всего каталога» нужен отдельный источник:
партнёрский фид или внешний catalog-data provider — под него уже создан
интерфейс `CatalogProvider` (`MarketplaceProvider → CatalogProvider`).

## Где вставить ключи

`.env` (копия `.env.example`, только backend, никогда во frontend):
`OFOX_API_KEY`, `QWEN_*_MODEL`, будущие `OZON_CLIENT_ID/OZON_API_KEY`,
`WILDBERRIES_API_KEY` (для seller-функций). Проверка: `GET /api/status`
(`aiMode`, `demoMode`, `providers.*`).

## Ограничения живья WB

Только 1-я страница выдачи (топ популярного), фильтр цены/размера —
кодом поверх, остатки неизвестны (`availability.inStock: null` — честно),
тексты отзывов не тянем (только счётчики), фото-хосты могут дрейфовать.
