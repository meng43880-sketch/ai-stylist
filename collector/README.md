# collector/ — домашний мост каталога (MVP)

Два сборщика, сервер один (`POST /api/collector/push`, источник `homefeed`):

* **Основной — `../ext/` (расширение для Chrome/Яндекс Браузера).**
  Запросы идут из живого браузера (куки, отпечаток) — wbaas пропускает
  то, что режет у node-скриптов. Кнопка «Собрать» + автопрогон каждые 6ч.
* **Запасной — `collect.js` (node).** Работает, только если сеть пускает
  скриптовый доступ к WB (VPN/дата-центры режутся сразу).

## Запуск

```powershell
node collector/collect.js
```

Настройки — только из `backend/.env` (в git не идёт):

```ini
COLLECTOR_KEY=<тот же секрет, что на сервере>
COLLECTOR_BACKEND=https://xxx.onrender.com   # куда пушить; локально http://127.0.0.1:8001
```

На сервере (Render → Environment) должны быть:

```ini
COLLECTOR_ENABLED=true
COLLECTOR_KEY=<тот же секрет>
```

Расписание: Планировщик заданий Windows → каждые 6 часов.
ПК должен быть включён — без свежего пуша данные протухают за 24ч
и тихо исчезают из выдачи (ничего не падает).

Проверка: `GET {backend}/api/collector/status` → `{count, ageMin, fresh}`.

## Быстрый откат

Мост отключается без нового кода за минуту:

1. Render → Environment → `COLLECTOR_ENABLED=false` (или стереть `COLLECTOR_KEY`) → Save.
   Сервис перезапустится, приёмник ответит 503, выдача вернётся на датасет/Takprodam.
2. Если надо откатить и код: `git revert <коммит-моста> && git push`
   (стабильная точка до моста — тег `pre-homefeed`).
3. Домашний скрипт просто не запускать — без пушей мост сам пустеет за сутки.

## Честно про серость

Системный сбор чужого каталога нарушает правила WB: возможен троттлинг,
капча или бан домашнего IP. Скрипт идёт вежливо (пауза 2.5с, 1 страница
на запрос, ~24 запроса за прогон), но риск не нулевой. Это MVP-мост,
а не постоянная архитектура: долгоживущий путь — фиды с договором
(Takprodam/Lamoda) и официальный Partner API.
